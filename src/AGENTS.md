- Home tiles, report preview and hourly strip use the dark `.weather-dark`/`.weather-product` token scope in styles.css; opened detail pages use `.weather-detail` (brand blue, night-blue controls, white text) and reset `.leaflet-container`/`.weather-light` to light tokens, because map overlays and the embed-shared local forecast are built for light surfaces; `.weather-surface` stays light.
- Region map time choice in app pages uses the shared radar FilmstripTimeline via the `filmstrip` prop; embeds keep the old slider, because existing WordPress iframes must not change.
- Public weather pages mark their wrapper `.weather-page`, which turns `body` and the view-transition backdrop brand blue, because phones tint the status bar from the body during tile transitions; embeds/admin keep the light body.
- Pull-to-refresh (pull-to-refresh.tsx, rules in lib/pull-refresh.ts) runs only on the home page in the installed web app and refetches router + queries without a reload, because browsers already ship the gesture and maps on detail pages need vertical drags.
- Home region map mounts directly from the SSR-safe desktop media-query snapshot, never gated by hydration or return-transition promises; desktop-only code/data preloading stays, because delayed browser signals left preview placeholders stuck and phones must not mount the map.
- src/router.tsx dehydrates every successful SSR query into the page and hydrates it before React starts, because suspense queries otherwise refetch during hydration and one hanging request left the whole page unclickable (no tiles, no region map); client-only (`ssr: false`) pages prefetch without awaiting and render controls with a loading state for the same reason.
