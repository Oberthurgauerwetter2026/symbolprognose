# Project rules
- Accumulation maps use explicit per-render phase palettes (no shared mutable palette); recent sums refresh through a deduplicated cache with request-managed background lifetime and a one-hour stale limit, because concurrent embeds must not leak modes or abandon updates.
- MeteoSwiss local-forecast ingestion selects the greatest timestamped STAC asset key with a usable href per parameter, because a daily item contains multiple hourly runs and dictionary order must never pin forecasts to midnight.
- Live weather products use a shared SourceFooter outside the map instead of Leaflet attribution controls; static/no-JS alternatives match its wording, so publisher, data and active map-layer credits appear once.
- Forecast PNG URLs are content-addressed and published before the manifest; cleanup retains recent generations so interrupted ingests and open tabs remain safe.
- Missing radar images are loading failures, never evidence of dry weather; never cache fallback renders under a missing URL.
- Radar playback timing lives in a pure, tested timeline module; render time and the snapped filmstrip time are separate so transitions cannot move labels early.
- Radar nowcast runs in 5-minute steps from the measurement without any intensity fade until :55 before the first full model hour at or after measurement+75 min (at least the current-time next full hour), so the model takes over seamlessly at :00 with no gap; filmstrip compression starts after the last nowcast frame.
- Motion estimation accepts quasi-stationary fields down to 0 km/h (orographic stauregen stays put and still feeds the nowcast; model handover is a hard cut at the full hour without overlay blending); only the approach warning (`_lead_fields`) and the auto-thunder drift text still require ≥5 km/h, because stationary rain has no approach.
- Nowcast intensity tendencies use motion-aligned 15–20-minute raw radar observations with bounded, damped local growth/decay in scripts/_nowcast.py; content-addressed PNGs publish before region-max, match the exact source measurement, and retain recent generations. Missing/unreliable tendencies fall back to pure advection, leaving model forecasts and precipitation phases unchanged.
- The dense Open-Meteo forecast fetch is split across parallel GitHub runners (shards) and merged in one publish job, because one runner IP would exceed Open-Meteo's hourly request limit; any missing shard aborts publication.
- Precipitation phase is refined per map pixel with the committed DEM (scripts/terrain_elev_420x200.npy, same 420x200 bbox as radar); regenerate it whenever the radar bbox or raster changes, because model terrain is too smooth for snow lines.
- Forecast contour texture is stationary in native PNG coordinates, with weak-edge-only ingest roughening and subpixel edge sampling; retain bilinear sampling and unchanged strong cores to avoid coarse blocks or fabricated intensity changes.
- Map place labels are dropped by a pure, tested declutter step in Web-Mercator pixels (priority: large cities, then medium towns, then peaks, then local places), so adding a place never requires manual collision checks. A peak may carry a small label offset (labelDx/labelDy) that the same step honours, so a name can clear a crowded neighbour without the summit moving.
- Measured precipitation sums use MeteoSwiss CombiPrecip hourly grids accumulated incrementally by ingest_precip_sums.py inside the radar ingest (soft-fail), with station gauges as point labels; the model sum is only the fallback surface and the snow source, because radar+gauge analysis is the reference for fallen amounts.
- Freezing rain is a fourth precipitation phase (PNG alpha 200) decided per model point from raw 2 m temperature ≤ 0 °C, a freezing level well above ground and little model snow, then smoothly interpolated; it overrides rain/sleet/snow, because a warm layer aloft melts snow that refreezes on the frozen ground.
- Apply the shared terrain freezing-rain filter after phase interpolation in both radar and forecast ingestion; missing pixel elevations suppress only the freezing-rain override, because interpolation must not spread valley glaze onto mountains and normal phases must remain intact.
- Radar measurement phase corrects model 2 m temperature/dew point with live ground stations (MeteoSchweiz + own Weather Hub) and checks the freezing level against mountain stations (pseudo-sounding) via pure, tested functions in _phase.py; soft-fail to pure model, because local cold pools decide snow vs. rain vs. glaze. Forecast frames stay model-only.
- Model forecast frames are damped (not boosted) by a pure, tested reality check in scripts/_reality_check.py: the radar ingest publishes radar/wet-grid.json, and the model ingest scales model rain down only for the first 3 h where the advected upwind radar area is clearly dry; missing/stale radar (>45 min) or no coverage leaves the model unchanged, because only a confident measurement may overrule the model.

- Radar motion uses a ~15-minute frame pair (fallback 5 min), damps pixels that stay identical (orographic stauregen) unless the whole field is static, and nudges only the direction toward a steering wind blended from the 850/700 hPa model layer mean (850 dominant, because 700 hPa alone is foehn-prone) and the live Säntis wind via the pure, tested scripts/_steering.py (a clear radar pattern match, quality ≥ 0.6, is never nudged; otherwise steering weight grows as radar speed/quality drop and is at least 75 % below 15 km/h; speed always from radar; each source soft-fails), because 5-minute subpixel shifts are noise-dominated; a final pure, tested direction guard (centroid_track/guard_direction in _steering.py), applied only when the centroid drift agrees with the steering wind within 60° (multi-cell centroids fake motion), overrules any vector deviating >90° from the measured centroid drift of the last ~20 min and clamps 45–90° deviations, so the nowcast never runs backwards.
- Nowcast decouples motion from phase: the radar ingest publishes a stationary per-pixel phase field (radar/phase/, from DEM + live stations + model, scripts/_phase.py `phase_field_rgba`) and nowcast frames read the phase at the unshifted target location, because snow over the Säntis must turn to rain when it drifts into the lowlands; nowcast PNGs use the phase at each target time, and phase field/nowcast frames join the manifest's last measurement within 15 min, because the two manifests can be one ingest cycle apart.
- Nowcast stage 2: scripts/_flow.py derives a local block-matching flow field from the same ~15-min radar pair (blocks without signal inherit the global guarded vector; median-smoothed and deviation-limited) and the ingest semi-Lagrange-advects every nowcast PNG; such frames carry `advected: true` and the client must not shift them again, because one global vector cannot move cells and stationary stauregen independently.
- Sum maps use corner-clamped Catmull-Rom at ~2000 px width; prevents holes and zoomed blocks without changing classes or opacity.
- Gefallene Regensummen (Radar) werden lokal mit eigenen Weather-Hub-Stationen nacheichen (src/lib/station-blend.ts, getestet): Gauss-Radius ~7 km, Faktor-Schranke 2.5, trockene Fläche nie korrigiert, weil CombiPrecip private Stationen nicht kennt und defekte Sensoren keine Flecken erzeugen dürfen.
- Gefallener Neuschnee kommt aus CombiPrecip × stündlichem Schneeanteil (sums_phase_at in ingest_radar.py: DEM + Stationen + ICON-CH1, inkrementell in radar/sums/phase.npz) über ingest_precip_sums.snow_cm und retained_step (Bodenwärme zehrt ersten Schnee auf schneefreiem Boden über 0 °C, Grad-Stunden-Schmelze; ohne Pixeltemperatur keine Schmelze); Stunden ohne bekannte Phase zählen als fehlend und ab >25 % fällt die Fläche aufs Modell zurück, weil vergangene Atmosphäre nicht nachträglich rekonstruierbar ist.
- Sums travel as base64 Int16 (0.1 units, src/lib/sums-pack.ts), unpacked via stable `select`; per-number payloads overflowed localStorage.
- Forecast snow is downscaled to the DEM (src/lib/snow-downscale.ts, tested; snow line sent in hm for Int16 packing), because the coarse model grid blurs terrain.
